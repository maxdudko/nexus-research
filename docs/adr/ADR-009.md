# ADR-009 — Product Experience Routing, State, and Research Lifecycle

**Status:** Accepted  
**Date:** 2026-10-23  
**Accepted:** 2026-10-23 — Gate 0, [`gate-0.md`](../specs/phase-9-product-experience/gate-0.md)  
**Target:** Alpha `v0.2.0` / Phase 9  
**Related:** [Phase 9 specification](../specs/phase-9-product-experience/spec.md), [implementation plan](../specs/phase-9-product-experience/plan.md), [ADR-005](ADR-005.md), [ADR-008](ADR-008.md), [Alpha vision](../specs/alpha-v0.2.0-vision.md)

## Context

The MVP web interface concentrates form, progress and history on `/`. Phase 8 added authenticated sessions, CSRF and user-owned research, but the web UI still uses a minimal `AuthGate` and login screen. A separate run detail route already exists.

Current implementation constraints:

- `apps/web/src/app/page.tsx` renders `ResearchWorkspace` inside `AuthGate`.
- `ResearchWorkspace` composes `ResearchForm`, `ResearchProgress`, `ResearchHistory` and `useResearchStream`.
- `useResearchStream` creates a scope on mount and again on retry. Scope creation is a rate-limited server operation, so passive page visits consume quota.
- The stream hook owns an in-memory reducer and `AbortController`; unmount aborts the request. There is no durable background execution or SSE reattachment.
- The API persists run history and reports independently of the UI and scopes them to the authenticated user.
- Next.js 16 App Router, React 19, Tailwind 4, Vitest and Testing Library are already in use; no UI kit or global state library is installed.

Phase 9 needs clear routes and user expectations while retaining existing security and research contracts.

## Decision summary

**Propose** a route-based application shell with a **local, request-scoped research session**, lazy scope allocation, reusable authenticated API client, and persisted history/report as the sole source of truth after navigation. Avoid a new backend or global state framework unless an implementation review demonstrates a concrete need.

The decisions below, and clarifications C1–C8, were accepted at Gate 0 after review of `development` at `53aa78a207a06e0ac570e16aa011b51e92f1e443`. Approval of this ADR is not a claim that the new routes are implemented.

## D1 — Routes and navigation

**Decision:** adopt these canonical routes:

| Route | Responsibility |
|---|---|
| `/login` | Credential entry and authentication errors |
| `/` | Authenticated dashboard and recent runs |
| `/research/new` | Create and monitor one request-scoped research attempt |
| `/history` | Paginated owner-scoped run history |
| `/research/[runId]` | Persisted run detail and report |

Use a shared authenticated application shell (navigation, identity/logout, theme, main landmark). Keep login visually separate from the authenticated shell. Prefer App Router layouts/route groups where useful; the exact folder structure is an implementation detail.

**Why:** each screen has a single purpose, direct links survive refresh, and history/report no longer depend on an active research form. A dashboard makes first-time onboarding clearer.

**Alternative rejected:** keep everything on `/` and add visual tabs. It preserves tight coupling between draft/stream and history, complicates navigation and reduces deep-link clarity.

**Alternative deferred:** folders, workspaces, advanced search, a public marketing site and account settings routes.

## D2 — Session and client-state ownership

**Decision:** keep four distinct state domains:

1. **Authentication identity:** resolved through `GET /api/v1/auth/me`, managed by a small shared auth boundary; no browser-readable session token or user identity as an authorization source.
2. **Draft/active research:** reducer-driven state in `/research/new`; includes question, optional `File`, scope ID, SSE progress and abort controller. Never treat it as durable.
3. **Persisted history/report:** fetch from owner-authorized `GET /research/runs` and `/runs/{runId}`. Re-fetch on page entry and account change; no localStorage/sessionStorage cache of private report bodies.
4. **Presentation:** theme, menu/drawer, disclosure states, etc. No global store needed for these.

Reuse and refactor `research-session.ts`, `use-research-stream.ts`, `sse.ts`, `lib/api.ts` rather than creating parallel session machines. Shared presentational components may be extracted from existing research UI.

**Why:** minimizes duplicate sources of truth and preserves well-tested state transitions.

**Alternatives rejected:** global Redux/Zustand store for all research; keeping full research state alive across navigation as an implicit background runner; storing uploaded PDFs in browser storage.

## D3 — Lazy scope allocation and submission ordering

**Decision:** no scope is created on page mount or passive navigation. On the first valid, explicit research submission:

```text
Validate question and optional PDF
  → POST /research/scopes (owned scope, exactly once for this attempt)
  → optional POST /evidence/pdf (index into that scope)
  → POST /research/stream (question + same research_id)
  → reconcile persisted run by run_id
  → navigate to /research/[runId] when available
```

The scope mint and PDF indexing are asynchronous **submission states**. Disable duplicate submission throughout mint/upload/stream. A failed scope mint does not trigger ingestion or stream. An indexing failure does not silently fall back to web-only research.

A deliberate **new attempt** allocates a new scope; the previous run is not resumed. Keep the selected question and (when still present in memory) the `File` reference for an explicit retry. A successful prior upload into a different scope does **not** imply the new scope contains that evidence; re-index the selected PDF when retrying.

**Why:** prevents quota waste on navigation, respects ownership, and makes PDF-first behavior explicit.

**Trade-off:** an abandoned attempt can leave an empty research scope or indexed evidence with no run. This is already a backend domain concern; cleanup/retention is outside Phase 9 and must not be implemented by deleting scopes on page unload.

**Alternative rejected:** mint scope on every mount; mint client-side UUIDs; implicitly reuse old scope across retries.

## D4 — Streaming, navigation and truthful recovery

**Decision:** one browser route owns one active POST SSE request. Reuse existing `parseSse` and reducer. The browser may show last-known progress, heartbeat and stall detection, but never invent percentage completion or background continuation.

- **Stop:** abort the active request, reflect interruption and reconcile history if a run ID exists. Stop is not pause.
- **Route change/unmount:** abort the request; optionally warn through an in-app navigation affordance when a stream is active. Do not rely on `beforeunload` to guarantee server cancellation or warn for every browser exit.
- **Successful terminal event:** fetch persisted run detail; navigate to the report route only when the expected run is available.
- **Unexpected EOF/disconnect:** use existing run ID to reconcile; if stored status is `running`, show an unconfirmed state. No auto-resume, no invented report.
- **Page refresh/reopen:** use owner-scoped persisted run status only. A stored `running` row is **last known state**, not proof that a graph is still executing.

**Why:** aligns the UX with the Phase 5 request-scoped execution contract and avoids false promises.

**Alternative rejected:** preserve a running request in a global provider across routes and present it as durable background execution. It would still die on tab close/reload and would blur ownership of cancellation.

**Future reconsideration:** a durable worker/job architecture and explicit status/reconnect API require a separate ADR, not a UI workaround.

## D5 — Authenticated shell and proxy boundary

**Decision:** keep FastAPI as the authority for authentication and resource ownership. The shared web shell can fetch `/auth/me` to render email and loading/error states; route protection in Next.js is a UX affordance, not a security boundary.

Preserve the Phase 8 same-origin proxy allowlist, signed session-bound CSRF contract, `HttpOnly` cookie and `no-store` handling. Do not forward arbitrary cookies, Authorization headers or user-controlled upstream targets. Logout must use CSRF protection and must not show success on a failed revocation. Clear in-memory private UI state when session ends; a new account always triggers fresh owner-scoped requests.

**Why:** a frontend-only authorization mechanism cannot replace service/database ownership checks, and changing proxy/auth contracts in a UI redesign creates disproportionate security risk.

**Alternative rejected:** client-side JWT storage, independent NextAuth/third-party auth layer, global report cache persisted across logins.

## D6 — UI architecture and styling

**Decision:** keep the existing Next.js/React/Tailwind stack. Introduce small reusable UI primitives only as duplication emerges (button, status, empty/error panel, page header, navigation). Reuse CSS theme tokens and `ThemeToggle`.

Prefer accessible semantic components and simple responsive navigation. Do not add a large UI kit, component generator, animation framework or client-state library solely for visual polish. A later dependency decision must justify bundle/maintenance/accessibility trade-offs.

**Why:** the phase is about a coherent journey and correctness, not a framework migration.

**Alternative considered:** shadcn/ui or a headless component library. Can be evaluated later for specific accessible controls, but is not required for Phase 9.

## D7 — Reports and source semantics

**Decision:** the existing structured report JSON and `CitationLink` are the source of report content. Improve visual hierarchy and contextual explanation without changing report schemas or treating evidence references as verified facts.

- Distinguish terminal statuses, warnings and limitations.
- Render model text as untrusted text, not raw HTML.
- URL citations may open a trusted-validated external URL; PDF references without stored original file are labels, not fake downloads.
- `failed`/`interrupted` have no invented report; a stored `running` run is shown as unconfirmed.

**Why:** the report domain is already stable and validated; Phase 9 should improve comprehension, not redefine research quality.

## D8 — API and testing policy

**Decision:** prefer existing endpoints and hand-written typed contracts. No new database migration or API route is planned. Gate 0 found no missing contract; see clarification C6.

Web unit/component tests use mocked API/SSE; integration/release smoke continue exercising real FastAPI and proxy paths. No paid provider calls in default CI. Include two-account privacy checks and keyboard/mobile manual walkthrough before declaring Phase 9 complete.

## Accepted clarifications

### C1 — Routes

`/` is the authenticated dashboard. The research form leaves `/`. Canonical routes are `/login`, `/`, `/research/new`, `/history`, and `/research/[runId]`.

### C2 — Shell and session loading

Authenticated pages share one App Router route group and one client session boundary. That boundary fetches `GET /api/v1/auth/me`.

- **200:** render the page. Key the private tree by user id so an account change cannot keep the previous tree.
- **401:** `replace` to `/login`. A `next` query is allowed only when it is exactly `/`, `/history`, `/research/new`, or `/research/` plus one canonical UUID. Anything else, including `//` and absolute URLs, is ignored and the destination is `/`.
- **Network failure, 403, and 5xx:** show an unavailable view with retry. Do not redirect to login and do not render private children.
- **`/login` when `me` is 200:** redirect to the allowlisted `next`, or `/`.

`/login` stays outside the authenticated group. The root layout keeps the document shell and the theme init script. It does not overlay the theme button. There is no Next.js middleware auth and no second auth framework. Route protection remains a usability control.

### C3 — Logout

Logout stays `POST /api/v1/auth/logout` with the CSRF header.

- **2xx:** drop in-memory private state and go to `/login`.
- **401:** the session is already gone. Go to `/login` without describing that as a successful revocation.
- **Any other failure:** stay on the page, keep the displayed identity, and show a retry error.

### C4 — Lazy scope and submission

No layout, dashboard, history page, or idle `/research/new` mount calls `POST /research/scopes`. On explicit submit:

```text
Validate trimmed question (10–2000) and optional PDF
  → creating_scope: POST /research/scopes once
  → optional POST /evidence/pdf
  → POST /research/stream with that research_id
```

The stream request must include the id just minted. Omitting it is forbidden: the API mints another scope when `research_id` is null, and a PDF indexed into the first scope would not be on that run.

`scope_failed` does not upload or stream. An upload failure does not open the stream. A synchronous guard rejects a second submit before the first await. 429 shows the API message and `Retry-After` when that header is an integer. The client does not schedule a billable retry.

A new attempt mints a new scope and re-indexes the in-memory `File` when one is still selected. Question and file are discarded on leaving the route, including on 401. They are not written to browser storage. An abandoned scope is left in place.

The scope UUID is not primary UI copy.

### C5 — Leaving, stop, and recovery

Unmount of `/research/new` aborts the active request and invalidates the generation token. While the phase is `creating_scope`, `uploading`, `streaming`, or `stalled`, an in-app navigation away from that route asks first: leaving stops the request, and it does not continue in the background. Stay returns focus to the page. Leave aborts and navigates. Do not register `beforeunload`.

Stop aborts and does not navigate to the report. If a run id is already known, refresh the persisted status into the local session. Do not present that as success. Terminal SSE still navigates only after the persisted run is fetched. Unexpected EOF reconciles the same way and does not mark `completed` from EOF alone.

A stored `running` row is last recorded state. The list uses `created_at`. The detail page uses `updated_at` and says execution is not confirmed. No spinner is driven only by that status.

### C6 — No backend change

Gate 0 found no missing field required for history or reports. Do not add `is_live`, `progress_percent`, `original_pdf_url`, `can_resume`, or `updated_at` on the list. Dashboard requests `limit=5`. History requests `limit=20`. Both use the existing cursor.

Private web fetches for `/auth/me`, run lists, and run detail use `cache: "no-store"`. That does not change the API. Auth responses already send `no-store`.

### C7 — Visual direction

Keep the Tailwind tokens in `globals.css` and the `max-w-2xl` column. Do not add a sidebar or a component library.

The authenticated header contains the product name, Dashboard, New research, History, the signed-in email, logout, and the theme toggle, plus a `main` landmark. When the row does not fit, including at 320 CSS px, a button named Menu discloses the nav under the header. The disclosure does not cover the page, does not trap focus, and closes on Escape and on navigation. `/login` has its own header with the theme toggle and no authenticated nav.

### C8 — Report copy

Reuse `ResearchReportView` and `CitationLink`. Add one plain-text statement that a citation identifies a retrieved source and does not prove the report is correct. PDF page refs stay non-links. `failed` and `interrupted` keep an explicit no-report state.

## Consequences

### Positive

- Clear, directly addressable product flows and simpler component responsibilities.
- Existing engine, auth and report semantics preserved.
- No scope quota spent by browsing; no accidental suggestion of durable jobs.
- Smaller reviewable PRs with deterministic tests.

### Costs and risks

- Refactoring the stream hook may introduce duplicate submissions, lost aborts or regressions in PDF retry behavior; cover these with reducer and integration tests.
- Moving the auth boundary can cause redirect loops or private-data flashes; explicitly test session expiry and account switching.
- A user who leaves the new-research route can interrupt the request; copy and navigation affordances must explain this honestly.
- Client-side-only navigation warnings cannot guarantee cleanup on browser/process termination.
- Responsive navigation and status announcements require manual accessibility verification beyond unit tests.

## Checks completed at acceptance

1. Map existing `/auth/me`, logout, CSRF and proxy behavior; preserve Phase 8 invariants.
2. Confirm exact route structure and the one-owner-per-stream lifecycle.
3. Verify scope mint happens only after valid user action and never in a layout or dashboard effect.
4. Confirm report/history endpoints remain owner-filtered, including admin accounts.
5. Verify all states, including stalled, disconnected and stale `running`, have truthful copy.
6. Confirm no new server endpoint, migration, provider call or persistent client cache is required.
