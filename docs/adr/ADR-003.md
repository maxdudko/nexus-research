# ADR-003 — Research-Scoped RAG Evidence Storage and Retrieval

**Status:** Proposed — awaiting approval  
**Date:** 2026-10-15  
**Decision owners:** Nexus Research project  
**Extends:** ADR-001, ADR-002  
**Supersedes:** None

## Context

Nexus Research Phase 2 discovers Tavily URLs and snippets but cannot search complete evidence. Phase 3 must ingest PDF/web text, embed passages and retrieve citations without coupling ingestion to Phase 4 LangGraph or Phase 5 UI. Existing PostgreSQL, Qdrant, FastAPI, async SQLAlchemy and OpenAI integration should be reused.

## Decision D1 — PostgreSQL is metadata source of truth; Qdrant is the retrieval index

Persist `Source` lifecycle and identity in PostgreSQL; store vectors, text and citation payload in a single versioned Qdrant collection. Qdrant is reconstructible from source content **only when the content is still available**; because original PDFs are not retained in Phase 3, document the re-upload requirement for rebuilding lost PDF indexes.

**Alternatives:** Qdrant-only metadata; PostgreSQL pgvector only; store full original files in DB.

**Why:** Clear lifecycle, relational constraints and Alembic learning, while using the already provisioned vector database.

**Trade-off:** No distributed transaction across stores. Must implement idempotent operations, failure states, recovery and stale-vector cleanup.

## Decision D2 — Mandatory research-scoped retrieval, not authorization

Require `research_id UUID` for ingestion and retrieval; include it in PostgreSQL identity and Qdrant payload; enforce it in the Qdrant query filter. Do not create Phase 4 `ResearchRun` prematurely.

**Alternatives:** Global shared index without filters; separate collection per research; introduce full research workflow model now.

**Why:** Single collection is simpler and scales better for MVP; scope filter prevents accidental evidence mixing.

**Security note:** A caller-controlled UUID is **not** tenant isolation or access control. API must not be exposed as a multi-user service without auth/authorization.

## Decision D3 — Text PDF via PyMuPDF, public HTML via HTTPX + Trafilatura

Extract PDF text page-by-page with 1-based page metadata; no OCR. Fetch bounded public HTML with HTTPX and extract article text using Trafilatura. Treat all extracted content as untrusted.

**Alternatives:** Tavily Extract, LangChain community loaders, Playwright, generic crawlers.

**Why:** Explicit control and educational value; no opaque document pipeline.

**Security condition:** HTTPX transport must defend against SSRF including DNS rebinding, redirect targets, IPv4/IPv6 private ranges and environment proxies. Simple URL validation or preflight DNS checks alone are inadequate. If a safe transport cannot be implemented and tested, defer arbitrary URL ingestion or use a constrained trusted extraction provider.

## Decision D4 — Explicit deterministic chunking and passage provenance

Normalize text; split deterministically with bounded overlap. Start with token-aware ~800/120 if a compatible tokenizer is installed; otherwise name units as characters. Preserve PDF page numbers and web URLs. Stable point IDs include source/content/version/chunk index.

**Alternatives:** Semantic chunking, LLM-generated chunks, splitting entire PDFs across pages.

**Why:** Easy to debug and evaluate; page-level citations remain meaningful.

**Trade-off:** Simple chunking may break semantic context; measure retrieval quality before optimizing.

## Decision D5 — OpenAI embeddings and versioned Qdrant collection

Use a separately configured OpenAI embedding model, default `text-embedding-3-small`, Cosine similarity and expected vector dimension (normally 1536). Collection name carries schema/index version. Validate dimensions and distance before writes; do not silently recreate mismatched collections.

**Alternatives:** Local sentence-transformers, multiple embedding providers, pgvector, hybrid retrieval.

**Why:** Consistent with OpenAI-first Phase 2 and low operational overhead.

**Trade-off:** Embedding API cost, network dependence and reindexing when model/dimensions/chunking change.

## Decision D6 — Bounded request-scoped ingestion with idempotent recovery

For Phase 3, synchronous-in-request ingestion is acceptable only for small inputs and strict deadlines. Store source status in PostgreSQL; upsert deterministic Qdrant IDs; mark INDEXED only after success. Ensure concurrent ingestion of the same source cannot race; changed content must not leave stale active vectors. On failure mark FAILED and allow retry/reconciliation.

**Alternatives:** Celery/Redis queue, distributed transactions, fire-and-forget FastAPI BackgroundTasks.

**Why:** Keep the educational scope small before durable LangGraph workflows.

**Trade-off:** Requests can be interrupted; original PDFs are not stored; no guaranteed background completion. Phase 4/5 can revisit durable jobs.

## Decision D7 — Retrieval produces evidence, not answers

`/api/v1/evidence/search` returns top-k scored passages with stable source references. It never calls a chat model or synthesizes claims. Scores are similarity measures, not factual confidence.

**Alternatives:** Implement RetrievalQA or a complete agent now.

**Why:** Separate retrieval quality from generation and grounding. LangGraph will consume evidence in Phase 4.

## Decision D8 — Optional credentials and offline CI

Embedding credentials are optional at startup. Unit tests use deterministic fake embeddings; integration tests use local PostgreSQL/Qdrant without paid provider calls. Live smoke tests are explicitly opt-in. Preserve existing health routes and error envelopes.

## Consequences

**Positive:** Reusable evidence subsystem, explicit source lifecycle, citation provenance, testable retrieval, bridge to LangGraph.

**Negative:** More moving parts, potential DB/vector inconsistency, web-fetch security complexity, provider costs, PDF re-upload for lost content.

## Compatibility

- Keep `nexus.main.create_app(settings)` and existing lifespan/session dependency.
- Extend `nexus.core.config.Settings`; do not repurpose Phase 2 chat model settings.
- Mount new `evidence` router under existing `/api/v1`.
- Add SQLAlchemy metadata/models and update Alembic `target_metadata` (currently `None`); ensure models are imported for autogeneration if used.
- Do not change `research/plan` or `research/discover` response contracts.
- Preserve Python 3.14, `uv`, Ruff/mypy/pytest and existing Docker Compose services.

## Revisit triggers

- Durable upload storage and async worker are required.
- Multiple authenticated users or tenants are introduced.
- Retrieval evaluations show a need for hybrid search/reranking.
- Embedding model or chunking strategy changes require reindexing.
- Web extraction complexity exceeds bounded safe HTTPX implementation.
