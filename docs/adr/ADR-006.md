# ADR-006 — Optional OpenTelemetry, Hybrid Evaluation, Offline-first CI

**Status:** Accepted for Phase 6 design  
**Date:** 2026-10-18  
**Related:** ADR-003, ADR-004, ADR-005; Phase 6 `spec.md` and `plan.md`

## Context

Nexus Research has a request-scoped FastAPI/SSE + LangGraph research workflow, PostgreSQL checkpoints and domain-backed history, Qdrant retrieval and OpenAI/Tavily integrations. A working report does not establish retrieval quality, citation support, reliability or cost. Existing `GraphUsage` counts logical calls and omits provider-managed retries. Phase 6 must add trustworthy measurements and failure regression coverage without introducing operational infrastructure beyond the MVP.

## D1 — OpenTelemetry-compatible tracing is optional and fail-open

**Decision:** instrument run, graph node and tool/provider boundaries with OpenTelemetry APIs. Tracing is disabled by default; exporting is optional, configured explicitly. JSON structured logs remain useful without any collector. Keep tracing context out of checkpoint state. Instrument the FastAPI lifespan and graph child tasks carefully.

**Why:** portable traces without vendor lock-in; spans complement checkpoint snapshots and domain history.

**Alternatives:** LangSmith mandatory (rejected: SaaS dependence, data exposure/cost); JSON-only logs (rejected as sole mechanism: weak span correlation); self-hosted Jaeger/Tempo mandatory (deferred: unnecessary infrastructure).

**Trade-offs:** extra dependencies and instrumentation maintenance; OTel spans alone do not guarantee actual provider token visibility.

## D2 — Privacy-first telemetry and low-cardinality metrics

**Decision:** allowlist safe span/log fields; exclude prompts, raw source content, vectors, secrets and full URLs. Keep run IDs in spans/logs, not global metric labels. Observability failures never alter domain outcomes.

**Why:** untrusted web/PDF content and private uploads may pass through the pipeline; observability must not become an exfiltration channel.

**Trade-offs:** harder content-level debugging; opt-in local reproduction with synthetic fixtures preferred.

## D3 — Separate logical budgets, observed usage and cost estimates

**Decision:** do not repurpose `GraphUsage`. Add separate optional per-operation observations and cost estimates with explicit provenance (`provider`, `estimated`, `unavailable`). Unknown SDK retries remain unknown. Price tables are versioned and not assumed current. Unknown token counts must not produce a falsely precise `$0.00`.

**Why:** budget enforcement and billing telemetry have different semantics.

**Alternatives:** infer tokens from character counts as exact (rejected); count logical calls as billable requests (rejected); full vendor billing reconciliation (deferred).

**Trade-offs:** incomplete totals in some LangChain wrappers; report partial/unknown coverage honestly.

## D4 — No new mandatory database tables for observability

**Decision:** start with spans/logs and versioned evaluation JSON artifacts; add no per-call PostgreSQL writes. A compact persisted run aggregate may be proposed later if UI/reporting requires it and a migration is justified.

**Why:** reduces transaction overhead and avoids coupling success to telemetry persistence.

**Alternatives:** SQL table per span/provider call (rejected); storing metrics in LangGraph state (rejected: checkpoint bloat).

## D5 — Deterministic offline evaluation is the PR quality gate

**Decision:** commit a small versioned authored corpus, retrieval result fixtures, citation/grounding gold labels and pure scoring functions. CI must run without API keys, Tavily, OpenAI or external network. Frozen outputs test scorer and pipeline invariants; live semantic quality is measured separately.

**Why:** reproducible, cheap, fast CI; avoids flaky probabilistic gates.

**Alternatives:** live API evaluation on every PR (rejected: cost/flakiness); no quantitative evaluation (rejected).

**Trade-offs:** offline fixtures cannot establish production retrieval quality or detect provider model drift.

## D6 — Hybrid grounding: deterministic invariants + optional LLM judge

**Decision:** deterministic citation/provenance checks are mandatory. A separate opt-in structured LLM judge evaluates claim support against bounded cited excerpts; calibrate with human-labeled examples. Judge cannot edit the report or route LangGraph execution.

**Why:** existence of `E3` does not prove that passage entails the associated claim.

**Alternatives:** citation IDs only (insufficient); judge as sole truth (rejected: probabilistic, correlated errors); human-only every run (too expensive for MVP).

**Trade-offs:** judge results vary across models/prompts; record versions, confidence/uncertainty and agreement, not absolute truth.

## D7 — Failure-injection tests are deterministic and security-aware

**Decision:** inject failures at existing provider/service boundaries and verify bounded retries, safe error codes, partial/insufficient reports, resource limits, SSRF rejection, prompt-injection containment, domain commit ordering and request cancellation. No live malicious network targets in CI.

**Why:** reliability is behavior under failure, not only happy-path test coverage.

**Trade-offs:** tests simulate failures and cannot guarantee recovery after OS/process crashes; Phase 5's best-effort cancellation contract remains.

## D8 — Preserve request-scoped lifecycle and product contracts

**Decision:** no queue/worker/automatic resume, no SSE event contract change, no new public diagnostics endpoint, no alteration to report schema or existing LangGraph topology unless a verified defect demands it. Telemetry must be non-invasive.

**Why:** Phase 6 is hardening and measurement, not a product rewrite.

## D9 — Evaluation thresholds are baseline-driven

**Decision:** CI blocks structural failures and deterministic regressions. Informational live quality/cost metrics are reported but do not gate PRs. Add quality thresholds only after the dataset and baseline are measured and reviewed.

**Why:** arbitrary scores create false confidence or flaky CI.

## Consequences

**Positive:** debuggable runs, reproducible evaluation, safer failure behavior, measurable cost coverage and portable telemetry.  
**Negative:** additional testing and versioned datasets; instrumentation must be maintained as provider wrappers evolve.  
**Follow-up:** Phase 7 may optionally configure an OTLP collector for the demo and publish a measured evaluation baseline. Background jobs, auth and durable resume remain out of scope.
